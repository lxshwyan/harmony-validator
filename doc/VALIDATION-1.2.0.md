## 修复与新增

- 四条新回归用例在 1.1.0 上全部失败、原有 232 条通过；修复后全部通过。
- 修复 JSON Schema oneOf 重叠匹配、组合/引用/常量的同级约束遗漏，以及空字符串与 Unicode 长度边界。
- 上下文通过可选尾参数贯穿内置容器和效果包装；并发调用不依赖全局上下文。
- extend/merge 的字段覆盖清理过期可选标记。
- deepPartial 扩展至数组、字典、元组、nullable/default/transform；第三方可实现 DeepPartialSchema。
- 异步批量新增 concurrency/timeoutMs，保持输入次序，异常或超时后停止派发。
- 新增 interop/execution 入口、独立 API 12 消费工程，并纳入 verify.sh。
- 续补 Union/Intersection/When 的 deepPartial，保留原始 Schema、元数据、回调及分支选择；修复 When 条件函数未接收 ValidationOptions，覆盖同步/异步校验与解析。
- 扩展完成 Lazy 递归/相互递归的更新转换，判别联合保留有效判别字段要求；修复继承属性误选分支和 Lazy 描述失败后的状态清理。
- 新增 inspectJSONSchema、可选 strict 导入及 JSON Pointer 诊断，布尔 Schema 支持；修复数字/布尔空字符串误判，诊断不向子字段前进的引用循环。
- 新增取消订阅/退订、独立请求子令牌、超时通知和第三方异常清理；String/Number customAsync 可读取本次选项。
- 新增 composition/form 按需入口、中英文高级用法与可编译消费示例；修复表单销毁后仍派发依赖校验的问题。

## 使用边界

- timeout 结束等待并通知独立子令牌；底层请求必须主动响应通知才会停止。concurrency 限制批次条目，不限制单条目的内部并发。模拟远程请求不等于真实网络适配验收。
- deepPartial 支持 Lazy 与判别联合；不支持输入对象本身带循环引用，保留原回调，不自动改写不具备扩展接口的第三方包装。局部更新不代表完整数据可省略必填字段，合并后应再用完整 Schema 校验。
- JSON Schema 导入仍是常用子集。默认宽松，strict/onDiagnostic 可拒绝或报告不支持能力；严格模式不是完整元 Schema 校验，不保证标准合规或无损重新导出。
- 消费构建仍有工具链生成声明的严格类型警告，构建成功。本轮不能以此前 1.1 的设备验证替代 1.2 真机验证。
- entry/ 的原有表单联调改动保持原状。

## 复现

在工程根目录运行 `./scripts/verify.sh`。只重测消费工程运行 `bash scripts/verify-consumer.sh`。
构建出的对比 HAP 在 `external-consumer/build/consumer-main.hap` 和 `consumer-lite.hap`。
真机运行需先为独立消费工程配置对应设备的有效开发签名，再构建、安装并检查页面显示 `PASS 1.2 consumer`。本轮确认设备仍连接且工程 signingConfigs 为空，没有重复尝试安装已知无签名包。

详细示例和逐项真机清单见 [中文高级指南](ADVANCED-1.2.0.md) / [English guide](ADVANCED-1.2.0-en.md)。
